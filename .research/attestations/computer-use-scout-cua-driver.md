## Attested details

1. **Full-desktop scope.** Cua ("computer-use 2.0") ships Cua Drivers: "Background computer-use driver for any agents. Speaks MCP over stdio; drives native macOS apps without stealing focus." It drives native desktop apps on macOS, Windows, and Linux "in the background — agents click, type, and verify without stealing the cursor or focus." Linux supports X11 and compositor-specific Wayland routes with explicit limits for raw background input. (top-level `README.md`; `libs/cua-driver/README.md`, header)
2. **MCP as the agent boundary.** "MCP-capable agents connect directly to `cua-driver mcp`; shell-oriented agents and automation can use `cua-driver call`." The Python (`cua_driver`) and TypeScript (`@trycua/cua-driver`) SDKs call the same in-process native Rust runtime through generated UniFFI bindings over a versioned C ABI; the language packages "contain no language-native MCP facade... MCP remains implemented by the `cua-driver` executable as the runtime-neutral agent boundary." (`libs/cua-driver/README.md`, "Integration surfaces")
3. **Tool surface.** The CI-pinned expected-tools manifest lists 50+ base MCP tools including desktop control (`click`, `double_click`, `right_click`, `drag`, `scroll`, `hotkey`, `press_key`, `set_value`, `move_cursor`), app/window management (`launch_app`, `kill_app`, `list_apps`, `list_windows`, `set_window_frame`, `invoke_menu`, `bring_to_front`), introspection (`get_accessibility_tree`, `get_desktop_state`, `get_window_state`, `get_screen_size`), browser-specific tools (`browser_navigate`, `browser_click`, `browser_type`, `browser_pointer`, `browser_download`, `browser_dialog`, `get_browser_state`), sessions (`start_session`, `escalate_session`, `list_sessions`, `get_session_state`), recording (`start_recording`, `get_recording_state`, `install_ffmpeg`), trajectory replay, and agent-cursor visualization (`set_agent_cursor_enabled`, `set_agent_cursor_motion`, `set_agent_cursor_theme`). (`.github/scripts/cua-driver-mcp-compat/expected-tools.json`)
4. **Permission modes.** Three modes: `standard` (promptless default), `bounded` (admits only tools/resources in a reviewed manifest via `CUA_DRIVER_CAPABILITY_MANIFEST_FILE` + `CUA_DRIVER_CAPABILITY_MANIFEST_APPROVED`), and `unrestricted` (requires `--dangerously-bypass-approvals`). The mode is fixed at process launch. Attaching to an existing logged-in Chromium profile is explicit opt-in: `cua-driver mcp --grant existing-profile`. Cua Driver "does not render its own authorization modal or banner." (`libs/cua-driver/README.md`, "Permission modes")
5. **macOS permission identity.** macOS Accessibility/Screen Recording grants attach to a responsible app identity. Supported launch modes: standalone `CuaDriver.app` with daemon, explicit direct MCP (`cua-driver mcp --direct`, uses spawning host's TCC attribution), or embedded via `EmbeddedCuaDriverHost` in the grant-owning app. "Directly spawning a raw `cua-driver serve` outside `CuaDriver.app` without embedded mode is unsupported." (`libs/cua-driver/README.md`, "macOS process identity and permissions")
6. **Observability and privacy-sensitive history.** Nightly macOS builds offer an opt-in, encrypted, local "Computer History" preview storing a strict metadata allowlist, with permission-gated `history_status`/`history_query` tools; it "never stores screenshots, typed text, clipboard contents, raw arguments or results, accessibility trees, paths, window titles, or URLs." Recording tools and a semantic agent cursor overlay provide observability of agent actions. (`libs/cua-driver/README.md`, "Computer History macOS preview"; expected-tools manifest)
7. **Sandboxed/remote execution.** The `cua` Python package (`pip install cua`) provides `Sandbox.ephemeral(Image.linux()|macos()|windows()|android())` with a uniform API (shell, screenshot, mouse, keyboard, multi-touch) across Linux containers/VMs, macOS, Windows, and Android, runnable on local QEMU or cua.ai cloud; BYOI images (.qcow2, .iso) are supported locally. Lume manages macOS/Linux VMs on Apple Silicon via Virtualization.Framework with unattended setup presets. (top-level `README.md`, "Cua - Agent-Ready Sandboxes", "Lume")
8. **Model coupling.** The driver layer is model-agnostic (MCP/CLI only). The separate `cua-agent` package is the AI agent framework for computer-use tasks; `cua-bench` evaluates agents on OSWorld, ScreenSpot, and Windows Agent Arena. A `--claude-code-computer-use-compat` mode reshapes the `screenshot` tool for Claude Code's vision grounding cue. (top-level `README.md`, Packages table; `libs/cua-driver/README.md`, "Claude Code computer-use compatibility")
9. **Distribution and skill.** The Rust daemon publishes Python wheels and npm packages from the same release artifacts; a canonical agent skill (`rust/Skills/cua-driver`) is published to ClawHub as `@cua/driver` (MIT-0 for the skill bundle; repo MIT). Documented client integrations include Claude Code, Cursor, Codex, OpenClaw, and Muse Code via stdio MCP config. (top-level `README.md`; `libs/cua-driver/README.md`, "Publishing the agent skill to ClawHub", "Muse Code")
10. **Platform maturity caveat.** The top-level README labels Linux driver support as "pre-release" in its section heading ("Background computer-use on macOS and Windows, with Linux pre-release"), while the driver README documents Linux X11/Wayland routes with explicit limits. (top-level `README.md`, section heading; `libs/cua-driver/README.md`)
