## Attested details

1. **Purpose and scope.** Browser Use is "The AI browser agent": it "lets an AI agent use a web browser the same way humans do — it opens pages, clicks buttons, types, and fills in forms." Scope is browser-only; there is no desktop/native-app automation in the source tree. (`README.md`; `browser_use/` package layout)
2. **Three integration surfaces.** (a) A Python library (`pip install browser-use`, Python >= 3.11) embedding an `Agent` with pluggable LLMs; (b) a CLI plus installable agent skill (`browser-use skill install`) aimed at existing agents ("Claude Code, Codex, Cursor, Hermes, OpenClaw"), positioned for one-off tasks; (c) an MCP server (`uvx browser-use --mcp` or `uvx browser-use[cli] --mcp`) for MCP clients. The README FAQ states the rule of thumb: "one-off tasks through an agent → CLI. Repeatable automation in code → Python library." (`README.md`, Quickstart and FAQ; `browser_use/mcp/server.py` module docstring)
3. **MCP server tool surface.** `browser_use/mcp/server.py` exposes direct browser-control tools (`browser_navigate`, `browser_click`, `browser_type`, `browser_scroll`, `browser_go_back`, `browser_screenshot`, `browser_get_state`, `browser_get_html`, `browser_extract_content`, tab/session management via `browser_list_tabs`, `browser_switch_tab`, `browser_close_tab`, `browser_list_sessions`, `browser_close_session`, `browser_close_all`) plus `retry_with_browser_use_agent`, which runs the autonomous AI agent as a fallback, and `mcp_cleanup_loop`. The server forcibly suppresses library logging to stderr/CRITICAL to avoid JSON-RPC interference on stdio. (`browser_use/mcp/server.py`)
4. **MCP client as agent tools.** Separately, `browser_use/mcp/controller.py` lets the browser-use agent itself consume external MCP servers: it connects to an MCP server over stdio, registers each remote tool as an agent action via `_register_tool_as_action`, keeps the session alive, and disconnects cleanly. (`browser_use/mcp/controller.py`)
5. **Domain restriction.** MCP tool calls and browser sessions accept an `allowed_domains` argument; the code notes that "SecurityWatchdog interprets allowed_domains=[] as 'no restrictions'," and a `tests/ci/security/test_mcp_allowed_domains.py` test exists. A `security_watchdog.py` module is present alongside crash, captcha, downloads, HAR-recording, popups, permissions, screenshot, and recording watchdogs. (`browser_use/mcp/server.py`; `browser_use/browser/watchdogs/`; `tests/ci/security/test_mcp_allowed_domains.py`)
6. **Isolation and profile handling.** `BrowserProfile` is a Pydantic template covering launch/connect/new-context arguments, with fields for `cdp_url` (connect to an existing browser), `is_local`, `use_cloud` (browser-use cloud browser service), and `cloud_browser_params`. Watchdogs include `storage_state_watchdog.py` and `local_browser_watchdog.py`. (`browser_use/browser/profile.py`; `browser_use/browser/watchdogs/`)
7. **Observability.** A dedicated `browser_use/observability.py` provides optional Laminar (`lmnr`) tracing with no-op fallbacks when lmnr is not installed and a debug mode gated on `LMNR_LOGGING_LEVEL=debug`. The agent package additionally produces history GIFs (`agent/gif.py`), browser video recording (`browser/video_recorder.py`), HAR recording, and screenshots (`browser_use/screenshots/`), plus a telemetry package (`browser_use/telemetry/`). (`browser_use/observability.py`; `browser_use/agent/gif.py`; `browser_use/browser/video_recorder.py`; `browser_use/browser/watchdogs/har_recording_watchdog.py`)
8. **Model coupling.** The library is multi-provider with first-party chat adapters for Anthropic, AWS Bedrock, Azure, Cerebras, DeepSeek, Google, Groq, LiteLLM, Mistral, Ollama (local), OpenAI, OpenRouter, OCI, and its own optimized `ChatBrowserUse` model. The README recommends `ChatBrowserUse()` claiming 3-5x faster task completion and offers a fully-hosted Cloud Agent as "recommended." (`browser_use/llm/`; `README.md`)
9. **Local and remote execution.** The open-source agent is free and "runs on your own machine"; the README also steers users to paid cloud browsers for "stealth, proxy rotation, and scaling" and to the hosted cloud agent API. A `browser_use/sandbox/` package exists in the source tree. (`README.md`, "Open Source vs Cloud"; `browser_use/sandbox/sandbox.py`)
10. **Vendor benchmark claims.** The README claims Browser Use is "#1 on the Odysseys leaderboard with an 87.4% average" over 200 long-horizon web tasks and references its own open-source benchmark repo. These are vendor-reported results, not independently verified here. (`README.md`, "Open Source vs Cloud")
