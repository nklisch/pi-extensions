## Attested details

1. **Purpose and scope.** "Skyvern automates browser-based workflows using LLMs and computer vision," providing a Playwright-compatible SDK with AI commands plus a no-code workflow builder. It uses "a swarm of agents to comprehend a website, and plan and execute its actions." Scope is browser-only. (README, introduction and "How it works")
2. **AI-augmented Playwright SDK.** Skyvern adds `page.act(prompt)`, `page.extract(prompt, schema)`, `page.validate(prompt)`, and `page.prompt(prompt, schema)`, plus `page.agent` commands (`run_task`, `login`, `download_files`, `run_workflow`). Standard Playwright actions accept an optional `prompt` parameter, with three modes: pure selector, pure natural language, or selector-first with AI fallback. (README, "SDK")
3. **MCP server surface.** The Skyvern MCP server "exposes 75+ tools across many categories" including browser session management (create/close/list/get/connect, including connecting to a local browser via CDP), browser actions (`skyvern_act`, `skyvern_navigate`, `skyvern_click`, `skyvern_type`, hybrid natural-language+selector mode), extraction (`skyvern_extract`, `skyvern_screenshot`, `skyvern_evaluate`), validation, credentials/login with stored credentials (Skyvern vault, Bitwarden, 1Password, Azure Key Vault) and automatic 2FA/TOTP, and workflow management (23 block types). (MCP docs, "What you can do")
4. **MCP deployment modes.** Three connection paths: OAuth browser sign-in against Skyvern Cloud (`https://api.skyvern.com/mcp/`, supported by Claude Code, Codex CLI, Cursor, ChatGPT custom connector), static API key against Skyvern Cloud, and a fully local stdio mode (`python -m skyvern run mcp` against a self-hosted server, requiring Python 3.11+). Tool surface is scopable: hosted scopes `operate`/`build`/`browser`/`lean` via URL or `X-Skyvern-Scope` header; local scopes via `--scope` flag, with documented tool counts (all=114, operate=29, build=60, browser=54, lean=32). (MCP docs, "Pick your setup", "Alternative: Local mode")
5. **Local and remote execution.** Local self-hosting runs via `pip install "skyvern[all]"` + `skyvern quickstart` (SQLite default at `~/.skyvern/data.db`, optional Postgres) or Docker Compose, exposing server + UI on localhost. Skyvern Cloud is the managed offering with anti-bot detection, proxy network, and CAPTCHA solvers. A tunnel mode (`skyvern browser serve --tunnel`) exposes a local Chrome with existing cookies/logins to Skyvern Cloud; the docs warn to always use `--api-key` with tunnels. (README, Quickstart; MCP docs, "Connect to your local browser")
6. **Observability and user intervention.** Skyvern supports livestreaming the browser viewport "so that you can see exactly what Skyvern is doing ... and intervening when necessary." MCP tools include network/console inspection and HAR recording. A packaged web UI at http://localhost:8080 displays tasks, workflows, and downloaded artifacts. (README, "Livestreaming", "Skyvern Features"; MCP docs)
7. **Local-profile reuse.** The Skyvern Chrome extension lets a local stdio MCP server drive the user's actual Chrome profile and tabs ("You explicitly choose which tabs to share, and the connection stays on your machine"). `--use-local-profile` clones auth-relevant data (cookies, saved passwords, local storage) without modifying the original profile. Persistent browser sessions and browser profiles appear in the repository's database migration history. (MCP docs, "Connect to your local browser"; repo file listing, alembic migrations)
8. **Model coupling.** Skyvern is multi-provider via LiteLLM: OpenAI, Anthropic, Azure OpenAI, AWS Bedrock, Gemini, Ollama (local models), OpenRouter, and any OpenAI-compatible endpoint. The agent's LLM must be configured by the operator; Skyvern Cloud bundles its own configuration. (README, "Supported LLMs")
9. **License and telemetry.** The open-source repository is AGPL-3.0, "with the exception of anti-bot measures available in our managed cloud offering." Telemetry is on by default and opted out with `SKYVERN_TELEMETRY=false`. (README, "License", "Telemetry")
10. **Vendor benchmark claims.** The README claims SOTA on the WebBench benchmark at 64.4% accuracy and best performance on WRITE tasks; these are vendor-reported results, not independently verified here. (README, "Performance & Evaluation")
